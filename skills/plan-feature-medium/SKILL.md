Plan (medium): $ARGUMENTS

"You" below is the main session. This is plan-feature-small with two critic agents in its review: you scout, plan and build yourself, and at the review the critics read the plan against the code beside your own check. Read plan-feature-small's SKILL.md (`../plan-feature-small/SKILL.md` from this file; if it can't be read, say so and stop) and follow its steps 1 to 8, with these differences:

- **Who reviews.** Small's "with no review agent" doesn't apply here. Where small offers to switch to `/ccinformer:plan-feature-medium` or `/ccinformer:plan-feature`, offer `/ccinformer:plan-feature` only.
- **Agent settings,** once in this run, before the first review: read `~/.claude/ccinformer/skills.json` (under `$CLAUDE_CONFIG_DIR` when set). Its `agents["plan-review"]` is what the user set for these critics in CCInformer's Debug › Settings (Plan review: critics); start from `{ "plan-review": <that entry> }`, or `{}`. Apply the task text's asks on top (`critics on Sonnet`), and tell the user in one line what changes, "the rest on the script's defaults". Once the plan file exists, write `Agent settings for this run: <the object as JSON>` (`{}` when empty) into its Context. From then on that line is the source: every Workflow call of this run passes `<object>["plan-review"]` as `agents`, left out when absent, never from a later read of the file.
- **Step 5 is replaced by this review.**
  - Read `plan-review.js` (`../plan-feature/plan-review.js` from this file) and run it with the Workflow tool, its whole content as `script`, and args `{ context, requirements, plan, files, round: 1, split: true, lenses?, agents? }`: `plan` the plan file's path, `files` the 1 to 30 files the plan touches, `lenses` at most 3 of the planning settings' extra lenses (`{key, focus}`, a lowercase key of letters, digits and `-`, other than correctness, fit and gaps). Two critics run in the background: one on correctness and gaps, one on fit and your extra lenses.
  - **While they run, do your own check:** intent (it does what the user asked and meant, honours their decisions, stays in scope) and what spans the two halves (a problem that is partly correctness or gaps and partly fit, such as a shape a fix in one half would change in the other). Don't redo their lenses.
  - **When it returns,** check every blocker and should-fix against the code, fold in the real ones and drop the wrong ones. Read a `fallback` result's `unparsed` lines like the rest; a half listed under `missingLenses` gave nothing, so check those lenses yourself. Each blocker and should-fix gets one line for Context, starting `[critic: <lens>]` or `[main session]`. An `error` is run once more.
  - **Round 2:** when round 1 found a blocker, or the fixes changed the contract, a checkpoint or a "done when", run it once more with `round: 2`, `previous: { findings, changes }` and `files` the files those changes touch, with your own check of those changes beside it. No third round here: what is left goes to the final check.
  - If the review shows the task is larger or riskier than it looked, small's question about `/ccinformer:plan-feature` applies.
- **Step 7's "Check every late change" is replaced by the final check.** If anything changed after the last round (the user's answers included), run the script once more with `round: 'final'`, `split: true`, `changes` (each change since the last round, one per line) and `files` the files they touch, with your own intent check of those changes beside it. Fold in the real findings, tagged `[critic: final]` or `[main session]`; an `error` is run once more. Skip it when nothing changed. What changes after it (such as feedback on ExitPlanMode) is named in Context as unreviewed.
- **Step 7's Context line** reads "reviewed by 2 critics (plan-review.js) and the main session, N rounds", then the final check's result (or "no final check: nothing changed"), the files each lens checked in the last round, each blocker and should-fix in one tagged line with what changed, and every change made after the final check, unreviewed.
